The problem

Most agent systems combine proposal, execution and self-reporting. That makes it difficult to establish:

  • who acted,
  • who authorized the action,
  • what evidence was used,
  • whether execution stayed in scope,
  • and whether an independent party can reconstruct the event.

The constitutional answer

Invariant: Proposer ≠ Judge ≠ Executor ≠ Witness.

01

Human sovereign

Holds constitutional authority and unconditioned veto. Decides boundaries.

02

AAA attention

Recommends attention priority and plans cognitive flow; does not authorize.

03

arifOS authority

Constitutional gatekeeper. Evaluates invariant floors; judges, does not execute.

04

A-FORGE execution

Executes allowable actions in bounded sandboxes; does not certify itself.

05

FRAME witness

Independent telemetry observer. Probes reality; does not judge.

06

VAULT999 record

Cryptographic ledger. Stores hash traces; does not establish truth alone.

07

Human acceptance

Human acceptance is separate from machine consequence. Final outcome confirmation.

What remains open

Demonstrated: 2 bounded properties Open: 4 end-to-end gaps Kernel status: Unmeasured is not a pass

Verified actor

Signing path exists; observed calls unsigned; actor_verified=false.

Acceptance test: every irreversible action carries an Ed25519 signature verifiable by an independent verifier.

Receipt fidelity

Invocation telemetry lacks governance fields; one kernel HOLD observed as ok:true.

Acceptance test: every invocation record carries a governance verdict field, whose transport outcome is independent of its verdict.

Sink agreement

One failed ledger event was omitted by organ counters.

Acceptance test: ledger sinks agree on the same set of failure events; checksums match cross-ledger.

Independent reconstruction

No external verifier is bound.

Acceptance test: one competent outsider can install the package, reproduce a refusal, attempt an unsigned action, observe rejection, inspect evidence, and reconstruct the event without federation access.
