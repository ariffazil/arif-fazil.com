## Why evaluation foundation comes first

The 2026-10-05 directive says:
> "Your next concrete build should be the evaluation foundation for the website upgrade: establish representative reader journeys, evidence checks, authority failure cases and a reproducible baseline; then improve the shared navigation and one complete domain journey against those tests."

Without an evaluation foundation, slice 2 (shared nav) and slice 3 (Earth → Money → Evidence journey) would be **shipped without a way to know if they work**. The 9-pattern reference catalog and the 2-layer nav design are good design ideas, but they are *ideas*. Evaluation converts ideas into measurable claims.

The 8 dimensions named in the directive (human clarity, truthfulness, retrieval, forecasting, reliability, authority, efficiency, maintenance) are the **measurement axes** for the foundation. They are not collapsed into one composite — per the directive: *"Do not hide these behind one composite score."*

This slice produces the **regression collection** that all future slices will be measured against. It is the only slice that does not change the live site; everything after it does.

## Slice 1 deliverables (concrete, falsifiable, in proposal_zones only)

### 1.1 — Five representative reader journeys

`forge_work/proposals/fi003-qwen/mission-2026-10-05/eval/journeys.md`

Each journey is a concrete browser test:
- Persona, starting URL, goal, expected path, success criterion (in seconds + visible evidence)
- Falsification: a specific failure mode that the journey would detect

Personas chosen to span the surface and the user:
1. **Journalist** verifying a PETRONAS claim → tests `/vitals/` + `/institution/` + the citation discipline
2. **Student** reading an essay on AI governance → tests `/words/` + `/words/writing/` + reading hierarchy
3. **Developer** checking if they can integrate with arifOS → tests `/forge/` + machine doors + the docs discipline
4. **Verifier** checking the seal chain → tests `/999/verify` (the journey that **fails today** — see T0)
5. **First-time visitor** learning who Arif is → tests `/` + `/institution/` + the 30-second comprehension rule

### 1.2 — Evidence check schema

`forge_work/proposals/fi003-qwen/mission-2026-10-05/eval/evidence-checks.md`

For each page-class, the schema lists:
- The evidence fields that MUST be visible (source, date, units, citation, confidence)
- The epistemic-label vocabulary (OBS / DER / INT / SPEC) used
- The "verified outcome" test — is there a closed loop from claim to source to verification?
- The failure cases (claim without source, dated > 1 year without refresh, etc.)

Five page-classes covered: hub · article · dashboard · machine · constitutional-page.

### 1.3 — Five authority failure cases

`forge_work/proposals/fi003-qwen/mission-2026-10-05/eval/authority-failures.md`

Each case is: setup → action → expected detection → expected response. Covering:
1. Agent creates a new canon file without F13 seal — file-authority FAIL-CLOSED must catch this
2. Mutation of seal chain without sovereign authority — verifier must reject
3. Public page exposes sovereign identity key (F11) — leak detector must catch
4. Action taken without scope declaration (F12) — must HOLD
5. Vet of evidence on unverified state (F2) — must downgrade confidence

These become the regression cases the federation can replay.

### 1.4 — Reproducible baseline

`forge_work/proposals/fi003-qwen/mission-2026-10-05/eval/baseline-2026-10-05.json`

Generated by a single script that probes all 86 surfaces in `surfaces.json` and records:
- HTTP status
- Content-Type
- Body bytes
- Title
- First meta description
- Redirect chain resolution

The script is committed to `forge_work/proposals/fi003-qwen/mission-2026-10-05/eval/probe-baseline.py` so it can be re-run on demand. Today's run is the **T₀** measurement; every future slice must be measured against it.

### 1.5 — Evaluation harness blueprint (not yet built)

Documented but **not built this slice**: a Playwright-driven harness that can replay the 5 journeys against any build and emit a per-journey score. The blueprint is at `eval/harness-blueprint.md`. The build is **slice 1.5 follow-up** (or pushed to slice 5 depending on cycle pressure). This avoids pulling a heavy new framework (Playwright) into the install queue before the foundation is in place.
